# Desert Arena · 攻守对战模式（实验）

> 状态：实验变体，不替代 v1.0 正式赛。
> 规则实现：`engine/oracle/rules_siege.js`（冻结 `engine/oracle/rules.js` 未修改）
> 规则清单：`engine/oracle/MANIFEST_siege.json`
> 实验结果：`results/siege/结论.md`

---

## 1. 模式定义

一方**守擂**（side 0），一方**进攻**（side 1）。地图地形仍由 seed 确定性生成，但双方不再对称：

- 守方在母舰周围有**工事**，攻方起始点**没有任何防御设施**；
- 胜负只看**母舰是否被摧毁**；
- 原 VP 点改为**矿场**，矿场产出 CU，用于生产单位；
- 时间到而守方母舰仍存活，判**守方胜**（攻方未能完成摧毁）。

## 2. 胜负与结束

按优先级：

1. 守方母舰被摧毁 → **攻方胜**（`level=1`）。
2. 攻方母舰被摧毁 → **守方胜**（`level=1`）。
3. 守方所有单位死亡（含工事）→ **攻方胜**（`level=2`）。
4. 攻方所有单位死亡 → **守方胜**（`level=2`）。
5. `turn >= tickLimit` 且守方母舰存活 → **守方胜**（`level=3`）。
6. 双方母舰同时被毁 → 平局（`level=0`）。

> “单位全部死亡”指该方所有存活单位（含 WALL/TURRET）都被清除。若守方只剩工事、母舰还活着，游戏继续，攻方仍需摧毁母舰。

## 3. 时间与初始配置

| 项 | 值 |
|---|---|
| tickLimit | 1200（60 s 逻辑时间；实验配置，可调） |
| tick | 50 ms；决策预算 120 ms；init 2000 ms |
| 守方 | 母舰 HP = 实验变量；3 LAV + 1 SALVAGER；700 CU；24 工事点 |
| 攻方 | 母舰 HP 3000；4 LAV + 1 SALVAGER；900 CU；0 工事点 |
| 基础收入 | 1.5 CU/tick |
| 工事布置阶段 | 前 80 tick，每 tick 最多 1 个 |

母舰 HP 是**配置基础值**；守方研究 A1/A2 装甲后，上限 ×1.22。生产、科技、弹道、地形、坡度、视野等其余规则沿用 `rules.js`。

## 4. 矿场（替换 VP）

原 4 个 VP 点改为 4 个矿场：

- 半径：`VP_RADIUS`（4.2 逻辑格 = 16.8 世界格）。
- 占领：半径内只有一方非结构单位 → 该方占领；双方都有 → contested，无收入。
- 收入：占领方 **+0.8 CU/tick**；矿场内每有 1 台 SALVAGER，额外 **+1.2 CU/tick**。
- 储量：每个矿场 **600 CU**，采完枯竭（owner 保留，但无收入）。
- 矿场收入直接进 `cu`，用于 `produce`；不再有独立的 `res` 采集点。
- 母舰不参与矿场占领（与旧 VP 规则一致）。

`hello.mines` / `tick.mines` 字段：

```json
{"id":0,"x":1011,"y":399,"owner":-1,"contested":false,"amount":600}
```

`owner`：`-1` 无主/争夺，`0` 守方，`1` 攻方。

## 5. 工事

| 工事 | HP | 射程 | 伤害/ROF | 工事点 | 说明 |
|---|---:|---:|---|---:|---|
| `WALL` | 520 | 0 | 无 | 1 | 阻挡移动；可被炮弹摧毁 |
| `TURRET` | 280 | 9 逻辑格（36 世界格） | 14 / 10 tick | 3 | 固定火力；`neutral` 模式自动开火 |

规则：

- 只有守方（side 0）能放；攻方的 `fort` 动作会被拒绝。
- 只能在**布置阶段**（`turn <= 80`）放；之后 `fort` 被拒绝。
- 必须在守方母舰 **34 世界格**内；不能在山脉；不能与其他单位重叠（<2 格）。
- 每个工事消耗对应工事点；预算不足时拒绝。
- 非法放置只记 `rejected`，**不判故障**。
- 工事不占人口、不参与生产；`WALL` 无武器；`TURRET` 在 `neutral` 模式下自动索敌。

动作：

```json
{"type":"fort","kind":"WALL","x":420,"y":300}
{"type":"fort","kind":"TURRET","x":500,"y":360}
```

每 tick 最多 1 条 `fort`；`kind` 只能是 `WALL` / `TURRET`。

## 6. 协议新增字段

### hello

```json
{
  "mode": "siege",
  "roles": ["defender", "attacker"],
  "mines": [{"id":0,"x":1011,"y":399,"amount":600}],
  "siege": {
    "defenderSide": 0, "attackerSide": 1,
    "mothershipHp": 1250, "attackerMothershipHp": 3000,
    "fortBudget": 24, "placeTicks": 80,
    "fortCost": {"WALL":1,"TURRET":3},
    "fortRadius": 204, "fortTypes": ["WALL","TURRET"],
    "mineRate": 0.8, "mineAmount": 600, "mineSalvage": 1.2, "mineRadius": 100.8
  }
}
```

`vp` 字段保留为空数组，`res` 为空数组；旧 Bot 不会误读。

### tick

- `mines`：矿场状态（含 `owner` / `contested` / `amount`）。
- `me.role`：`defender` / `attacker`。
- `me.fortBudget` / `me.fortsPlaced`：工事点与已放置数。
- `me.minesOwned` / `me.mineIncome`：矿场数与累计收入。
- `me.phase`：`place`（前 80 tick）/ `battle`。
- `score[]`：`mines` / `kills` / `losses`。

### result

新增：`mode:"siege"`、`mothershipHp`、`attackerMothershipHp`、`destroyed`、`destroyedAt`、`mines`、`roles`。胜负仍用 `winner`（0 守方 / 1 攻方 / -1 平局）与 `level`。

## 7. 运行

```bash
cd war_of_desert

# 编译攻守 Bot
go build -o bots/bin/attacker.exe ./workspace/siege/attacker
go build -o bots/bin/defender.exe ./workspace/siege/defender

# 单局 smoke
go run ./cmd/siege -smoke -hp 1250 -seed 20261201

# HP 扫描（单 HP，40 seed）
go run ./cmd/siege -tickLimit 1200 -fortBudget 24 \
  -hps 1250 -seeds 20261201-20261240 -workers 4 \
  -out results/siege/hp1250_clean.csv
```

`cmd/siege` 默认使用 `engine/oracle_host.js` + `engine/oracle/rules_siege.js`，不会碰旧 `rules.js`。

## 8. 实验结论（摘要）

| HP | 摧毁率 | 95% CI |
|---:|---:|---|
| 3000 | 0.0% | 0.0% ~ 8.8% |
| 2200 | 0.0% | 0.0% ~ 8.8% |
| 1800 | 5.0% | 1.4% ~ 16.5% |
| 1600 | 12.5% | 5.5% ~ 26.1% |
| 1500 | 12.5% | 5.5% ~ 26.1% |
| 1400 | 17.5% | 8.8% ~ 31.9% |
| 1300 | 25.0% | 14.2% ~ 40.2% |
| **1250** | **32.5%** | **20.1% ~ 48.0%** |
| 1200 | 35.0% | 22.1% ~ 50.5% |
| 1000 | 47.5% | 32.9% ~ 62.5% |

- 目标 20%～45%：**1200 / 1250 / 1300**。
- 推荐：**1250 HP**（32.5%，最接近区间中点）。
- 1400（17.5%）低于目标，1000（47.5%）高于目标。
- 40 seed/HP × 10 HP = 400 局，0 故障，400/400 `verify.ok=true`。

详见 `results/siege/结论.md`。

## 9. 与 v1.0 的关系

- `rules.js` 与 `rulesHash=906f1b14` 未改动；v1.0 的 40 局结果仍可复现。
- 攻守模式是独立变体，`rulesHash` 由 `mode + mothershipHp + fortBudget + placeTicks + ...` 共同决定，不同 HP 指纹不同。
- 攻守模式目前只用于实验与平衡标定；要转正式赛季，需补选手包、许可、回放查看器与沙箱（见 `Dev/设计审查_正式版v1.0_20261113.md`）。
