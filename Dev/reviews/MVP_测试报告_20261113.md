## 3. 仍然存在的问题

### P0-1 斩舰路径没有发生，胜利仍是 VP 单轴

- 100/100 局都是 L2（时间到比 VP），**0 局 L1**；100 局 0 斩舰。
- VP 差中位 895，Tactical 92:8；Greedy 1925 发/116 杀仍 8 胜。
- 说明“母舰被毁”这条第一级判定链在实际对局中不可达/不被追求；击杀也不能转化为胜利。

**修订建议**：

1. 降低母舰 HP（3000 → 1500～2000）或提高对母舰伤害；加“母舰受损”事件/护盾阶段。
2. 让击杀有战略收益：击杀掉落 CU、减少对方人口上限、或 VP 占领速度与存活单位挂钩。
3. 加一个“专门冲母舰”的参考 Bot，把 L1 变成必须防守的威胁；验收：100 局 L1 ≥10%。

### P0-2 Tactical 92:8，平衡过度偏向 VP/科技

- Tactical 只打 126 发、55 杀，却 92 胜；Greedy 1,925 发、116 杀，8 胜。
- 4 个 VP 让双方各拿各的；Tactical 的 BFS 认领 + 科技/分配滚雪球，Greedy 的兵力优势无法转化为 VP。
- VP 差中位 895，说明大多数局不是“险胜”，而是“一方控住多数点”。

**修订建议**：

1. VP 几何改为 **1 中心 + 2 侧翼**，中心点双方等距、无遮挡；或加 VP 衰减/突然死亡。
2. 限制 VP 滚雪球：占点收益递减、或落后方获得补正。
3. 目标胜率：Tactical vs Greedy 在 50%～70%，不是 92%；验收：100 局胜负差 ≤40。

### P0-3 计分卡仍约一半是常数

- 母舰 100、算力 99.96、KD 50、保存 96.18、推进 95.03；约 **49.2 分**不区分对局。
- 保存兵力在“不生产、不损失”时接近 100；算力域在 0.06ms 量级测的是 IPC；推进效率仍与 VP 共用计数器。
- VP 与总分相关 0.647，仍以 VP/控制为主。

**修订建议**：

1. 删除“推进效率”或改为独立指标（前线推进距离/控制区变化）。
2. 保存兵力改为 `aliveCost/(initialCost+producedCost)` 或相对期望存活率。
3. 算力域移出排名，或改成硬预算（超时即故障）+ 校准后 ≤3%。
4. 加方差门禁：每个域 stdev >5；没有域在 >90% 对局取同一值；总分与 VP 相关 <0.8。

### P0-4 机制大量闲置

- 5/7 可生产兵种（SCOUT/RAILGUN/ARTILLERY 为 0）；7/20 科技；3 种模式全部 `obey`。
- 12 节点研究路线在 1200 tick 仍只走到 7 个；RAILGUN 订单没有落地。
- 说明“合成兵种/科技选择/单位自治”没有进入实际对局。

**修订建议**：

1. 让 SCOUT/RAILGUN/ARTILLERY 在 1200 tick 内可行：降造价/研究时间，或提高其战术价值（视野、远射、曲射）。
2. 参考 Bot 至少 3 种独立实现：正面推进、经济/科技、骚扰；让三种模式各有一个 Bot 使用。
3. 验收：兵种 ≥6/7、科技 ≥12/20、模式 3/3。

### P1-1 没有 BT/CI/并列，只有 2 个 Bot

- `tournament.js` 是积分榜：胜 1/平 0.5/负 0，按积分再按总分排序；没有 BT、没有 95% 区间、没有“相邻差 CI 含 0 记并列”。
- 官方 smoke 2 局；50 seed 探针也只有 2 个 Bot。
- 14 个模型参赛时，积分榜会退化成“谁抽到的对手弱”。

**修订建议**：

1. 加 BT：基准 Bot 锚 0；相邻差 CI 含 0 记并列；按地图/场整块 bootstrap。
2. 每人 80～120 局、固定地图池（20 张）× 全部对阵 × 换边。
3. 验收：前 5 名 CI 宽度 <120；至少出现 1 组并列。

### P1-2 交付/规范缺口

- 无 LICENSE、`README_en`、`CONDITIONS`、`prompt`、模型条件、Docker 沙箱、归档 HTML 回放、`challenge.js`。
- 正式集数规范：1 符合 / 6 部分 / 9 不符合；社区竞赛：3 符合 / 6 部分 / 4 不符合（详见设计审查）。
- `hello` 约 110KB/128KB；512² 前必须压缩/分块。

**修订建议**：

1. 加 LICENSE（MIT 或 CC BY-NC，与上游兼容）+ `THIRD_PARTY_NOTICES`。
2. 补 `README_en`、`CONDITIONS`、`prompt`、`bots/`、`replays/` HTML 播放器、`challenge.js`。
3. 至少 3～4 个模型试赛，记录工具/渠道/用时/事故；Docker 或独立进程 + CPU 预算。
4. 512² 前做 hello 压缩（zlib/分块/更强 RLE），验收：`hello < 64KB`。

### P2 细节

- `rules.js` 仍是 1769 行单文件、`Game` 56 个方法；迁移时按 `protocol/engine/scoring/io` 拆。
- 官方 smoke 2 局仍容易被误读为平衡结论；`arena.js` 输出应默认标注“smoke/unranked”。
- `Tactical` 的 12 节点路线只走 7 个；科技树与 1200 tick 仍不匹配。
- Go 半成品的引擎快照未同步 v0.11；若继续维护，需要新快照 + 新 `rulesHash`，并重跑历史赛季。

## 4. 修复后的投稿建议

**定位**：不是“正式赛季”，而是“**社区竞赛规则引擎 + 自包含本地测试环境**”。这一定位与 `Dev/MVP` 的实际状态一致，也能保留它最强的部分（引擎、10 套件、覆盖率、manifest、本地 runner）。

**最小可行清单**：

1. 首屏声明：社区非官方、规则引擎/测试环境、非模型榜、尚无模型参赛。
2. 加 LICENSE + `THIRD_PARTY_NOTICES`。
3. 补竞赛层：固定 seed 池 + 80～120 局/人 + BT/并列/CI；把 2 局 smoke 标为“不作平衡结论”。
4. 修计分卡：删/改推进效率、保存兵力改相对期望、算力移出排名；加方差门禁。
5. 修 VP/斩舰：1 中 + 2 侧，或 VP 衰减；让 L1 成为真实威胁。
6. 补交付：`README_en`、`CONDITIONS`、`prompt`、`bots/`、HTML 回放、`challenge.js`。

**如果做不到 1～4**：建议以“规则引擎/测试环境提案”投稿，明确“尚无模型参赛、尚无赛季、尚无排名”，让维护者按提案评审。
